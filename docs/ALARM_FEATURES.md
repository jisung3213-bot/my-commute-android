# 알림 10종 및 설정 탭 구현

## 적용한 기능

기존 **Java Android 앱과 무료 Firebase Authentication/Firestore, 직접 API 요청 구조**를 유지해.
알림은 모두 기본 ON이며 `설정` 탭에서 전역 ON/OFF와 개별 ON/OFF를 관리해.

| 번호 | 알림 | 발생 조건 | 동작 및 제약 |
|---|---|---|---|
| 01 | 출발 준비 | 권장 출발시각 15분 전(설정 가능) | 이름별 루틴에 AlarmManager 예약. 저장된 계획 소요시간 사용, 이동 추적 중 최신 도보시간이 확보되면 예약 보정 |
| 02 | 출발 권장 | 권장 출발시각 도달 | AlarmManager로 별도 예약 |
| 03 | 대중교통 도착 임박 | 확인된 차량의 실시간 ETA 5분 이하 | 사용자가 시작한 이동 추적 서비스에서 평가. 미검증·0초 ETA 제외 |
| 04 | 승차지 출발 | 차량 ETA - 현재 위치의 TMAP 보행시간 - 승차 준비 2분 = 0~설정 여유시간(기본 2분) | 최신 GPS/도보시간/유효 차량 ETA 필수. 이미 탑승 불가한 차량은 출발 권장하지 않음 |
| 05 | 환승 준비 | 현재 환승 구간의 다음 탑승 위치 반경 100m 지속 접근 | 현재 위치, 경로 진행단계 확인 필요. 선로 근접만으로 탑승 사실 확정하지 않음 |
| 06 | 하차 준비 | 제공기관 경로의 내릴 역 바로 앞 역 좌표 반경 95m 지속 접근 | 역 목록에 좌표가 없는 경우 발송 생략. 지하 구간 GPS가 없으면 미발송 가능 |
| 07 | 도착 지연 | 계획된 잔여 구간 소요시간으로 계산한 도착시각이 목표보다 5분 이상 늦음 | 위치로 추정된 현재 경로 단계 필요. 실제 차량별 ETA가 아닌 **계획 기준 지연 가능성** |
| 08 | 날씨 주의 | 출발 준비 시점의 1시간 이내 저장된 비·눈·저온 예보 | 01 활성화 시 준비 알림에 통합, 01 비활성화 시 별도 날씨 알림. 최신 예보가 없으면 추정 발송 금지 |
| 09 | 경로 이탈 | 위치 정확도 50m 이내, 경로 선형에서 150m+GPS 오차 이상 벗어난 상태 30초 | 한 번 경로 위에 있던 것이 확인된 후 평가. 경로 선형이 불완전하면 생략 |
| 10 | 목적지 도착 | 이동 시작 후 1분 경과, 최종 경로 구간 진행, 이전에 목적지 300m 밖에 있었고 현재 100m 이내 15초 연속 확인 | 해당 이동 완료 처리, GPS 추적 및 실시간 조회 종료. 알림 OFF여도 추적 자동 종료는 수행 |

### 시스템 구조

- `ReminderScheduler`: 각 계정의 **출근·퇴근별 현재 선택된 루틴**에 대해 01·02·08 예약. 대체 경로의 중복 알림 방지
- `ReminderReceiver`: Android 예약 알림 처리, 중복 검사 및 다음 예약
- `TrackingService`: 사용자가 위치 추적을 켜면 GPS 수집, 약 1분 간격 첫 탑승 차량 ETA 조회, 필요한 경우 5분 주기 보행시간 조회
- `TravelAlertMonitor`: 현재 위치, 경로 단계, 최신 ETA·보행시간을 통해 03~07·09~10 판단. 추측 알림 금지
- `AlertLedger`: 루틴·날짜·알림 종류·구간별 중복 방지 및 목적지 도착 완료 기록
- `AlarmSettingsStore`: 전체/개별 알림 ON/OFF, 출발 준비·차량 접근·승차 여유·지연 기준값, 기본 루틴 설정
- `SettingsActivity`: 하단 **설정** 탭, 설정 편집·저장, 알림 기록, 루틴 관리, 권한 화면, 로그아웃

### 저장과 동기화

- 알림 설정은 **계정별 SharedPreferences에 로컬 보관**하고 기존 Firestore `users/{uid}/settings/commute` 문서의 `payload.alarmSettings`에 함께 동기화해.
- 이름별 루틴과 선택한 **계획 소요시간**은 저장하지만, 대중교통 현재 ETA를 영구 저장하거나 미래 ETA처럼 사용하지 않아.
- 현재 위치에서 첫 승차 위치까지 실제 보행 API 시간이 확인되면 **출발 전** 출발시각을 보정할 수 있어. GPS 추적이 꺼져 있거나 데이터가 없으면 기존 저장 경로의 계획시간으로 예약해.
- 앱 UI를 닫아도 **사용자가 시작한 위치 추적 서비스가 유지되는 동안** 이동 중 알림을 평가해. 자동으로 백그라운드 추적을 시작하지 않아.

### 정확도 및 실행 제약

- **TAGO 403 인증 오류나 서울시 지하철 `barvlDt=0` 문제는 이 작업에서 해결된 것이 아니야.** 유효한 도착정보가 없으면 03·04 알림이 발생하지 않아.
- 실제 탑승 여부, 터널 내 위치 및 정차역은 기기 GPS로 확정되지 않을 수 있어. 확인할 수 없으면 05·06을 보내지 않아.
- 출발 준비 및 권장은 실제 현재 위치 정보가 없을 때 **저장 경로의 계획시간**을 사용해. GPS를 상시 강제 활성화하지 않아.
- 예약 시각 정밀도는 기기 알림 권한, Android 정확한 알람 권한과 배터리 정책의 영향을 받아.
- 현재 날씨 주의는 **이미 조회해 보관한 최신 예보**가 있을 때만 전송해. 알람 수신기가 백그라운드에서 임의로 인터넷을 호출하지 않아.
- 과도한 API 사용을 막기 위해 실시간 조회는 사용자가 시작한 서비스에서만 수행해. GPS/도착정보 조회 실패는 사용자에게 추정 알림으로 대체하지 않아.

## 검증

`AlertThresholdsTest`에 차량 도착, 승차 여유, 지연, 경로 이탈, 도착 조건 단위 테스트를 추가했어. Android 실제 빌드·실기기 실행·실제 교통 API·잠금화면 및 절전 상태 검증은 별도로 필요해.
