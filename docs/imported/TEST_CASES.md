# 기능 검증 체크리스트 (실기기 미수행)

## 정적 검증 후 실기기 검증할 시나리오

1. Firebase 설정 없이 빌드 → **데모 모드**에서 메인 진입, 일반 로그인 버튼 비활성.
2. 데모로 루틴 저장 → 앱 종료/재시작 → 로컬 루틴 유지.
3. 오늘 해당 요일/출퇴근시간 → 재실행 시 **TrackingActivity**로 바로 진입하되 GPS는 **자동 시작하지 않음**.
4. 루틴 출발시각 10분 전, 사전알림 15분 → 예정된 알림이 다음 활성 요일로 이동.
5. 우천 테스트 활성화 → 입력한 우천 계획 예상 소요시간과 추가 출발 알림이 선택됨.
6. 경유지 유형 식사/커피+시간 등록 → 각 시각 알림 예약, 실제 알림이 표시되거나 권한 문제로 실패하면 Room 기록.
7. 알림 권한 허용/거부 및 정확한 알림 권한 허용/거부 각각 확인.
8. 좌표 미입력 → 지도 상태 메시지 표시, 허구의 Polyline 생성 없음.
9. 유효 좌표만 입력 → 지도 마커 표시. 보행 모드+실제 TMAP 키 → 실 API 경로 확인.
10. 대중교통 모드 → 실시간 대중교통 경로를 그린 것처럼 표시하지 않음.
11. GPS 권한 허용 후 '추적 시작' → foreground 위치 알림 + 위치 갱신. '추적 종료' → 서비스 종료.
12. 데모 로그아웃 → 기존 알림 취소·GPS 추적 종료·로그인 화면, 루틴 데이터는 로컬에 남음.
13. Firebase 파일 설치 후 이메일 가입·로그인 → Firestore 사용자별 루틴 저장/재로그인 복구 (실제 콘솔 연동 시).

## 실제 데이터 연결 후 추가해야 하는 검증

- 서울시 API가 데이터 없음/통신 장애/지연/오래된 갱신시각 응답 시 '불명' 처리.
- 버스/지하철 정류장 ID, 노선, 상·하행, 회차, 첫차·막차의 다중 후보.
- 기상 격자 좌표와 예보 발표/대상 시간 일치 여부.
- 우천·강풍으로 자전거가 제외될 때 대중교통 혼합 경로로 대체되는지.
- 포그라운드 제한, 절전·Doze, OS 재부팅, 앱 강제 종료에 따른 알림 재예약.
- Firestore 동기화 충돌/재로그인/탈퇴 데이터 삭제.
