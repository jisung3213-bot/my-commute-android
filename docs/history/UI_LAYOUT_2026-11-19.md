# 2026-11-19 화면 레이아웃 점검

기준: 2026-11-19, `feat/isolated-alert-lab`.

## 기존 구조에서 확인된 위험 요소와 수정

| 화면 | 확인된 위험 | 변경 |
|---|---|---|
| 전체 하단 내비게이션 (`view_bottom_nav.xml`) | 5개 기본 `Button`이 가로 `weight=1`인 상태에서 Android 기본 최소 너비·패딩으로 좁은 화면에 잘림 가능 | 각 버튼 최소 너비 0dp, 좌우 패딩 0dp, 가운데 정렬, 48dp 탭 높이, 기존 ID 유지 |
| 출퇴근 루틴 등록 (`activity_custom.xml`) | 요일 5개를 한 줄에 배치해 작은 기기/시스템 큰 글자에서 겹침 가능 | 3개+4개 두 줄, 각 체크박스 유연한 너비, 기존 요일 ID 유지 |
| 출퇴근 루틴 후보/저장 목록 (`CustomActivity.java`) | 동적 `MaterialButton`의 긴 경로 문구·두 줄 요약이 좁은 패딩에서 가독성 저하 | 카드 텍스트 14sp, 상하 12dp·좌우 16dp 여백, 최소 터치 높이 56dp |
| 실시간 이동 (`activity_tracking.xml`) | 주요 정보 26~27sp 글자가 가로 공간이 좁은 화면에서 과도하게 줄바꿈 | 핵심 헤드라인·날씨 값 23sp, `wrap_content` 유지 |
| 실시간 이동 약도 (`RouteSchematicView.java`) | 커스텀 캔버스의 구간당 47dp 간격이 시스템 글꼴 크기에 비례하지 않음 | 글꼴 배율에 비례해 행 높이와 측정 높이 증가 |
| 홈 및 설정 (`activity_main.xml`, `activity_settings.xml`) | 스크롤 콘텐츠·하단 탭 높이의 배치 일관성 부족 | `fillViewport`·패딩 클리핑 설정 정리, 기존 스크롤과 하단 탭 분리 유지 |

### 변경하지 않은 기능

- 모든 화면의 `@+id`를 유지하고 기존 Java 리스너·알림 설정·경로 저장·지도·API 호출 기능을 변경하지 않는다.
- API 접근 정보 및 인증키를 UI에 표시하지 않는다.
- 실제 기기 크기와 화면 오류 캡처는 제공되지 않아 레이아웃의 문제 가능성이 높은 코드부터 수정한 **1차 안정화**이다. 화면 렌더링 완전 정상화 또는 접근성 완전 충족을 단정하지 않는다.

## 수동 QA 기준

1. **기기:** 에뮬레이터 API 34, 시스템 글자 크기 기본 및 크게(1.3배 이상), 좁은 화면 폭(약 320~360dp)에서 비교.
2. **하단 탭:** 홈/루틴/지도/이동/설정이 가로 폭을 넘지 않고 모두 눌리는지, 접근 가능한 터치 영역을 가지는지 확인.
3. **루틴:** 요일 7개가 겹치지 않으며 입력/선택/경로 결과 카드가 스크롤되는지 확인. 경로 명칭이 길어도 저장·선택 버튼이 짤리지 않아야 함.
4. **이동:** 출발 판단·날씨·경로 약도·차량 안내가 한 줄로 강제되지 않고, 글꼴을 확대해도 겹치지 않아야 함.
5. **설정:** 10개 알림 스위치, 4개 기준 분 설정이 스크롤되어 보이고 하단 탭에 가려지지 않아야 함.
6. **로그인/지도:** 키보드 열린 로그인 입력과 지도 컨테이너가 서로 침범하지 않는지 확인.
7. **기능 회귀:** 기존 탭 이동, 루틴 저장, 경로 검색, 알림 수신, 외부 API 응답 확인을 순서대로 실행해 예전 이벤트가 유지되는지 확인.

## 확인 범위

- GitHub에 저장된 변경 레이아웃 XML 5개의 태그 중첩·종결·중복 ID를 정적 검사했고 이상을 발견하지 못함.
- **Android Studio에서 APK를 빌드하거나 에뮬레이터에 실행해 시각적 레이아웃을 확인한 것은 아님.**

## 3개 주요 화면 정보구조 재설계 (2026-11-19)

사용자 제공 Android 화면 캡처 기준으로 다음 문제를 수정했다.

### 실시간 이동: 다음 대중교통
- 기존 한 문장에 섞인 **정류장명·노선·도착시간·다음 차량·탑승 여유**를 분리했다.
- 노선 유형 배지, 탑승 정류장/역, **현재 차량 ETA / 다음 차량 ETA 2열**, 탑승 가능성, 승차지까지 소요시간, 여유시간을 독립 TextView로 구성.
- 실제 TMAP/GPS/API 계산과 `live.arrival()`, `live.walkSeconds()`는 유지하고 **표시부만 재구성**했다. 정보 미확인/만료는 숫자를 추정하지 않고 대시 또는 보류 텍스트로 표시한다.
- `activity_tracking.xml`, `TrackingActivity.java`.

### 루틴 등록: 이동 장소
- 경로 이름, 출발지, 도착지, 경유지 설정을 **하얀 카드형 입력 패널**에 묶고 설명·입력 레이블 분리.
- 경유지 목록을 **제거 가능한 Material ChipGroup**으로 제공. X 버튼 클릭 시 임시 경유지 삭제 및 현재 경로 검색 결과 무효화. 이동 중 편집 제한은 유지.
- 실제 좌표 검색은 이전 `PlaceSearchActivity` 기반이며 임의의 자유 텍스트 좌표를 사용하지 않는다.
- `activity_custom.xml`, `CustomActivity.java`.

### 경로 검색 결과
- 기존 보라색 MaterialButton 한 개에 전체 구간 텍스트를 넣던 구성을 제거.
- **하얀 카드 + 경로 번호 + 총 이동시간 + 도보/환승/운임 요약 + 개별 구간**으로 분할.
- `구간 상세 보기 / 구간 접기` 기능 및 `이 경로 선택` 기능을 분리. 선택되면 보라색 테두리 및 `선택됨` 표시.
- 기존 API 결과 `TransitRoute`, 경로 선택 시 루틴 저장·서명 캐시·지도 미리보기 활성화 로직은 유지.
- `item_route_result.xml`, `bg_route_selected.xml`, `CustomActivity.java`.

### 검증 상태
- 수정 XML `activity_tracking.xml`, `activity_custom.xml`, `item_route_result.xml`, `bg_route_selected.xml`의 태그 중첩 및 ID 중복을 정적으로 확인했고 문제를 발견하지 못함.
- 변경 Java의 중괄호 균형 및 신규 ID 참조를 정적으로 확인함.
- **Android Studio에서 실제 빌드, API 호출 및 화면 스크린샷 검증은 하지 못했음**. 시각적 완성도를 보증하는 것이 아닌 사용자 화면 기준 리팩터링.
