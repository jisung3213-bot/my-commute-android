# 다음 단계

1. 보존한 TMAP 대중교통 호출을 Repository로 분리하고 실제 후보를 RouteLeg(도보/버스/지하철)로 파싱한다. 총시간/도보/실외대기/환승/자전거 포함 여부를 WeatherRouteRanker에 연결한다.
2. 기상청 예보와 한파 등 특보 어댑터를 추가한다. 데이터 유효시각·조회 실패·미확인 상태를 보존한다. 현재 수동 테스트 체크박스는 실제 날씨 표시와 분리한다.
3. 첫 탑승 정류장/역·노선·방향 ID를 서울시 실시간 도착정보에 매핑한다. GPS 접근시간과 탑승 여유를 계산해 못 타는 차량은 다음 차량/후보로 넘긴다.
4. 알림 갱신/중복 방지, 이동 세션의 현재 구간·실제 ETA, 데이터 노후화와 오프라인 처리를 연결한다. 서버 없는 상시 백그라운드 조회를 보장한다고 표시하지 않는다.
5. TMAP 지도 SDK/대중교통 경로 시각화, 로그 날짜 필터·상세와 동기화 상태 UI를 보완한다.
6. 권한 허용/거부, 재부팅, 절전, 날짜 변경, 우천+한파, 실제 정지/이동의 기기 시험을 수행한다.

식사·커피 등 편의시설 추천/알림은 사용자 지시에 따라 보류한다.
사용자의 실제 경로·시각은 개발자가 사전에 받아 넣는 값이 아니라 앱의 입력값이다.
