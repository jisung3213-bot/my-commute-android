## 3. 해결된 문제와 설계 선택

### 3.1 지하철 ETA가 빈 이유

- 서울시 지하철 실시간 API는 ETA 필드 `barvlDt`를 제공하나 값이 항상 양수는 아님.
- 사용자가 **2026-11-19 20:18:56 KST**에 실행한 12역 표본 조사: **총 150행 중 양수 67, 0초 83, 누락 0**.
- 광운대역(1호선) 6행 모두 0초, 서울역/시청/종로3가 등에는 일부 양수. 2호선의 조사 표본은 양수 비중이 높았음.
- 이에 따라 **정확하지 않은 ETA 숫자는 출력하지 않고**, 열차 상태·방면만 사용자 화면에 표시. 이 표본은 전 노선·전 시간대 통계가 아님.

### 3.2 GPS 추적 상태

- 위치 권한 및 기기 위치 서비스 상태를 확인하고 서비스 중지 사유를 화면에 표시합니다.
- 터널·겹치는 경로·기기 정확도에 따라 위치 판정이 제한될 수 있습니다.

### 3.3 추천 1개만 먼저 보여주는 이유

- 후보 여러 개를 모두 펼치면 사용자가 비교해야 할 정보가 과밀해짐.
- 기상·루틴 여유에 따라 점수로 순위를 매겨 **최상위 추천 1개**를 먼저 보여주고, 대체 경로는 버튼으로 펼침.
- 추천 순위는 사용자가 확정한 루틴 선택과 별개. 추천 결과가 표시됐다는 이유만으로 사용자의 기존 선택을 덮어쓰지 않음.
- 경로 정렬 로직은 `WeatherRouteRanker.rank()`에 있습니다.

## 4. Git 브랜치 역할 (현재 상태)

- `main`: 최신 통합 기준. PR #1과 #2가 병합된 브랜치이며 이 문서의 과거 기능 브랜치보다 새 버전입니다.
- `feat/isolated-alert-lab`: 알림 모의실험·GPS/추천 로직 검증을 실제 동작과 격리해 개발한 과거 기능 브랜치입니다. 지금의 `main`에는 당시 디버그 실험 화면을 그대로 보존하지 않았습니다.
- `feat/number-picker-inputs`: 숫자 선택 UI를 별도로 실험하기 위해 `main`에서 분기했습니다. UI를 확인한 뒤 PR #2로 병합했으며 이후 `main`에서 문서·접근성 개선도 이루어졌습니다.
- 개발 브랜치는 **안전한 변경·비교·되돌리기**를 위한 Git 분리입니다. `src/main`과 `src/debug`처럼 Android 빌드 소스셋을 나누는 것과는 별개입니다.
