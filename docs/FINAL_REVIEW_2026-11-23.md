## 2. 최신 기능/문서 불일치 조치

- README의 **과거 커밋 기준 전체 파일 목록**, '업데이트됨/올라감'과 같은 현재 의미가 불명확한 표기와 장황한 변경 내역을 제거하고 현재 기능 중심으로 재작성.
- `docs/MINUTE_PICKER_EXPERIMENT.md`가 **이미 `main`에 병합된 기능을 미병합 실험처럼 설명하던 문제**를 정정. 단순히 `git switch main`으로 옛 UI로 돌아갈 수 있다는 **잘못된 복귀 안내**도 정정.
- 사용자 가이드, 현재 아키텍처, UI 검증표, 개발 변천사에 **TimePicker + 분 입력 6개 NumberPicker** 및 실제 구조 반영.
- 검증 문서는 **PR #2 이전 에뮬레이터/빌드 기록과 PR #2 이후 미검증 상태**를 구분.
- 수업 안내에 맞춰 팀 규모·예산·보고서·발표·제출 항목을 표기하되 **가격·3개월 예산을 근거 없이 생성하지 않음**.

## 3. 코드 검토에서 발견한 항목

| 항목 | 검토 결과/조치 |
| --- | --- |
| `MinutePicker` 6개 입력값 | XML MaterialButton ID와 Java의 `attach/value/set` 호출 일치 확인. 루틴 0~180, 설정별 1~120/1~30/0~20/1~60/0~120의 기존 제한 유지 |
| 목표 도착시각 | `CustomActivity.pickArrival()`의 `TimePickerDialog` 유지 |
| 설정 저장 계약 | 정수 분값을 `AlarmSettingsStore.setThresholds` 및 `setDefaultMargin`에 전달. `Routine.marginMinutes` 형식 유지 |
| 취소 동작 | `AlertDialog` 취소 시 값 유지; 확인 시 `setTag`와 버튼 문구 갱신 |
| **접근성 설명문 갱신** | 루틴 전환 후 값만 갱신하면 콘텐츠 설명이 초기 수치로 남는 문제를 발견해 **`MinutePicker.set()`에서 설명문 동기화**하도록 수정. 전용 `R.id.minute_picker_accessibility_title` 사용 |
| 사용하지 않는 입력 검사 | 과거 숫자 입력 오류 처리의 잔여 코드는 동작을 방해하지 않음. 제출 직전 대규모 구조 변경보다 안정성 우선 |
| 실시간 이동·알림 | GPS/ETA의 정확성 검증을 보수적으로 유지. 영하 예보와 **공식 한파특보를 혼동하지 않도록** 설명 |
| Android SDK/보안 | `targetSdk 28`과 `BuildConfig` API 키 추출 가능성은 개발용 파일럿의 한계. 상용 출시 준비 완료로 표시하지 않음 |

## 4. 실행 미검증 및 주요 위험

**이번 검토에서 새로운 Gradle 빌드, 실제 기기 수신, Firebase 다기기 동기화, 실시간 API 호출, 네트워크/절전 종단간 시험을 수행하지 않았습니다.** 그러므로 코드상 명확한 불일치 일부를 수정한 것이지 모든 런타임 오류의 부재를 증명한 것은 아닙니다.

- 실제 Google/Firebase 설정 파일·API 사용 승인·TMAP 별도 SDK가 필요합니다.
- 일부 노선의 ETA가 0초이거나 방향/정류장이 매칭되지 않으면 차량 임박 안내를 보류합니다.
- 장시간 위치추적·정확한 예약은 Android 권한·제조사 배터리 정책에 좌우됩니다.
- 현재 `main`에는 과거 진단용 debug UI 및 JUnit 소스가 정리되어 있으므로 이 저장소 자체에서 이전과 동일한 회귀 시험을 실행할 수 있다고 주장하지 않습니다.
- **평가상 가장 큰 남은 위험은 제출 보고서의 가격 근거·3개월 예산과 발표용 최신 앱의 실행 재확인**입니다. 미확인 상태를 성공으로 기술하지 않습니다.
