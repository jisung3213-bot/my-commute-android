# 다음 단계

1. 대중교통 경로 공급자 API를 프로덕션 `network/`에 연결하고 실제 후보를 RouteLeg(도보/버스/지하철)로 파싱한다. 총시간/도보/실외대기/환승/자전거 포함 여부를 WeatherRouteRanker에 연결한다.
2. 기상청 예보와 한파 등 특보 어댑터를 추가한다. 데이터 유효시각·조회 실패·미확인 상태를 보존한다. 가상 기상 체크박스는 제거되었으며 API 응답 전에는 미확인으로 표시한다.
3. 첫 탑승 정류장/역·노선·방향 ID를 서울시 실시간 도착정보에 매핑한다. GPS 접근시간과 탑승 여유를 계산해 못 타는 차량은 다음 차량/후보로 넘긴다.
4. 알림 갱신/중복 방지, 이동 세션의 현재 구간·실제 ETA, 데이터 노후화와 오프라인 처리를 연결한다. 서버 없는 상시 백그라운드 조회를 보장한다고 표시하지 않는다.
5. TMAP 지도 SDK/대중교통 경로 시각화, 로그 날짜 필터·상세와 동기화 상태 UI를 보완한다.
6. 권한 허용/거부, 재부팅, 절전, 날짜 변경, 우천+한파, 실제 정지/이동의 기기 시험을 수행한다.

식사·커피 등 편의시설 추천/알림은 사용자 지시에 따라 보류한다.
사용자의 실제 경로·시각은 개발자가 사전에 받아 넣는 값이 아니라 앱의 입력값이다.


## GPS 탑승 판단 이후

- 이번 단계의 거리/도보시간은 **임시 직선거리 기반**이므로, 정확한 정류장 입구와 보행 경로 API 또는 공식 경로 데이터를 활용한 보정이 필요합니다.
- 실제 TAGO 정류장/서울 지하철 일치 검증 및 서버 응답 실기기 테스트 후, 사용자 명시적 동의와 API 호출량 제한을 전제로 재조회·선제 알림 및 경로 이탈 대응을 설계합니다.


## 다음 실제 연동 검증 순서

1. **서울 실시간 지하철 API**: \`trainLineNm\`, \`statnTid\`, \`updnLine\`, \`recptnDt\`가 TMAP 선택 경로의 첫/환승역 방향과 실제로 일치하는지 확인. 임의의 행선지를 다음역으로 간주하지 말 것.
2. **TAGO 버스정류소/도착 API**: 노선·방향·정류소 이름 유일성, 1·2차 버스 정보 필드 실데이터 확인.
3. **TMAP 보행자 경로 API**: 실제 거리/소요시간 정상 여부, 역 출입구와 승차 위치 차이에 따른 오차 측정.
4. **공식 기상특보/운행 장애 API**: 서비스별 이용 권한·지역 매핑·캐시·만료 기준을 확보한 다음 구현.
5. **안전한 출발 알림**: 확인된 차량·보행시간·사용자 승인 상태 및 재조회/중복 방지 정책을 마련하고 검증 후 도입. 현 단계의 근사치만으로 자동 알림을 발송하지 않음.
