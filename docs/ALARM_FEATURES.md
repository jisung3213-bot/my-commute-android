# 알림 10종 및 설정 탭 구현

## 적용한 기능

알림은 모두 기본 활성화되며 `설정` 탭에서 전체와 개별 알림을 조절할 수 있습니다.

| 번호 | 알림 | 발생 조건 | 동작 및 제약 |
|---|---|---|---|
| 01 | 출발 준비 | 권장 출발시각 15분 전(설정 가능) | 이름별 루틴에 AlarmManager 예약. 저장된 계획 소요시간 사용, 이동 추적 중 최신 도보시간이 확보되면 예약 보정 |
| 02 | 출발 권장 | 권장 출발시각 도달 | AlarmManager로 별도 예약 |
| 03 | 대중교통 도착 임박 | 확인된 차량의 실시간 ETA 5분 이하 | 이동 추적 서비스에서 평가. 미검증·0초 ETA 제외 |
| 04 | 승차지 출발 | 차량 ETA - 현재 위치의 TMAP 보행시간 - 승차 준비 2분 = 0~설정 여유시간(기본 2분) | 최신 GPS/도보시간/유효 차량 ETA 필수. 이미 탑승 불가한 차량은 출발 권장하지 않음 |
| 05 | 환승 준비 | 현재 환승 구간의 다음 탑승 위치 반경 100m 지속 접근 | 현재 위치, 경로 진행단계 확인 필요. 선로 근접만으로 탑승 사실 확정하지 않음 |
| 06 | 하차 준비 | 제공기관 경로의 내릴 역 바로 앞 역 좌표 반경 95m 지속 접근 | 역 목록에 좌표가 없는 경우 발송 생략. 지하 구간 GPS가 없으면 미발송 가능 |
| 07 | 도착 지연 | 계획된 잔여 구간 소요시간으로 계산한 도착시각이 목표보다 5분 이상 늦음 | 위치로 추정된 현재 경로 단계 필요. 실제 차량별 ETA가 아닌 **계획 기준 지연 가능성** |
| 08 | 날씨 주의 | 출발 준비 시점의 1시간 이내 저장된 비·눈·저온 예보 | 01 활성화 시 준비 알림에 통합, 01 비활성화 시 별도 날씨 알림. 최신 예보가 없으면 추정 발송 금지 |
| 09 | 경로 이탈 | 위치 정확도 50m 이내, 경로 선형에서 150m+GPS 오차 이상 벗어난 상태 30초 | 한 번 경로 위에 있던 것이 확인된 후 평가. 경로 선형이 불완전하면 생략 |
| 10 | 목적지 도착 | 이동 시작 후 1분 경과, 최종 경로 구간 진행, 이전에 목적지 300m 밖에 있었고 현재 100m 이내 15초 연속 확인 | 해당 이동 완료 처리, GPS 추적 및 실시간 조회 종료. 알림 OFF여도 추적 자동 종료는 수행 |

### 시스템 구조

- `ReminderScheduler`: 각 계정의 **출근·퇴근별 기본 루틴**에 대해 01·02·08 예약
- `ReminderReceiver`: Android 예약 알림 처리, 중복 검사 및 다음 예약
- `AutoCommute`: 자동 추적을 켠 경우 예정 출발 30분 전부터 출발 시각까지 출발지 500m 이내를 확인한 회차의 안내·알림 허용
- `TrackingService`: 자동·수동 시작 모두 최신 위치로 출발지 500m 조건을 확인한 뒤 이동 안내를 시작합니다. 약 1분 간격 차량 ETA와 필요한 경우 5분 주기 보행시간 조회
- `TravelAlertMonitor`: 현재 위치, 경로 단계, 최신 ETA·보행시간을 통해 판단. 추측 알림 금지
- `AlertLedger`: 루틴·날짜·알림 종류·구간별 중복 방지 및 목적지 도착 완료 기록
- `AlarmSettingsStore`: 전체/개별 알림 ON/OFF, 출발 준비·차량 접근·승차 여유·지연 기준값, 기본 루틴 설정
- `SettingsActivity`: 하단 **설정** 탭, 설정 편집·저장, 알림 기록, 루틴 관리, 권한 화면, 로그아웃

### 저장과 동기화

- 알림 설정은 **계정별 SharedPreferences에 로컬 보관**하고 기존 Firestore `users/{uid}/settings/commute` 문서의 `payload.alarmSettings`에 함께 동기화합니다.
- 이름별 루틴과 선택한 **계획 소요시간**은 저장하지만, 현재 ETA는 수집 시점과 유효성을 확인해 현재 차량 안내에만 사용합니다.
- 현재 위치에서 첫 승차 위치까지 실제 보행 API 시간이 확인되면 **출발 전** 출발 시각을 보정할 수 있습니다. 보정 데이터가 없으면 저장 경로의 계획시간으로 예약합니다.
- 앱 화면을 닫아도 실행 중인 위치 추적 서비스에서 이동 알림을 평가합니다. 백그라운드 자동 시작에는 위치 권한과 자동 추적 설정이 필요합니다.

### 정확도 및 실행 제약

- TAGO 인증 오류 또는 서울 지하철 `barvlDt=0` 응답 등으로 도착정보를 확인하지 못하면 03·04 알림을 생략합니다.
- 실제 탑승 여부, 터널 내 위치 및 정차역은 기기 GPS로 확정되지 않을 수 있어. 확인할 수 없으면 05·06 알림을 생략합니다.
- 자동 추적을 끈 경우 출발 준비·권장은 저장 경로의 계획시간으로 예약합니다. 자동 추적을 켠 경우 출발 시각까지 위치가 확인된 회차에서 예약 알림을 허용합니다.
- 예약 시각 정밀도는 기기 알림 권한, Android 정확한 알람 권한과 배터리 정책의 영향을 받습니다.
- 현재 날씨 주의는 **이미 조회해 보관한 최신 예보**가 있을 때만 전송합니다. 예약 수신기는 저장된 예보를 사용합니다.
- 이동 추적 서비스와 이동 화면은 조회 간격을 제한합니다. 도착 정보의 검증에 실패하면 관련 이동 알림을 생략합니다.

자동 추적이 켜진 회차는 예정 출발 30분 전부터 출발 시각까지 최근 60초 이내에 측정한 정확도 100m 이내 위치를 사용합니다. 수동 시작에서도 최신 위치를 확인하며, 위치 확인은 최대 30초입니다. **출퇴근 위치 안내 표시** 설정을 끄면 화면 문구가 숨겨집니다. 위치 조건은 계속 적용됩니다.
